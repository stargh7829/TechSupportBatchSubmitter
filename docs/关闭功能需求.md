# 技术支持关闭功能需求

记录日期：2026-06-15

状态：待受理查询关闭已在 `1.2.0` 实现；提交清单关闭和历史记录进入 `1.3.0` 实现。

应用中的“关闭”明确代表截图中的“受理并总结”流程。保存并核验工单进入
`已解决` 后即视为关闭成功，本版不再执行平台上可能存在的独立“关闭”步骤。

## 单条关闭

用户在“待受理查询”或“提交清单关闭”结果中点击某一行的“关闭”后，程序按以下固定流程执行：

1. 打开该技术支持单详情页。
2. 点击“受理并总结”。
3. 在总结页面保留“事件描述”原有引用值，不读取后覆盖，也不重新填写。
4. 将“原因分类”固定设置为 `数据疑问`。
5. 将“原因描述”固定设置为 `已处理`。
6. 将“解决方法”固定设置为 `修改数据`。
7. 将“解决方案”固定设置为 `已处理`。
8. 点击“保存”。
9. 保存后核验工单编号、标题及处理状态，成功后刷新查询结果。

平台实际“受理并总结”页面地址必须包含 `flag=11`：

`/xzsw/zcaseManager/toSolution.do?case_id={技术支持编号}&flag=11`

本版本不提供上述字段的自定义输入。

## 批量关闭

- 用户点击“批量关闭”后，只处理当前列表中已勾选的工单。
- 查询结果选择列提供“全选/取消全选”，全选只选择当前可关闭记录。
- 每条完成保存和结果核验后默认随机等待 5-10 秒，再开始处理下一条；界面可填写固定秒数覆盖默认区间。
- 单条保存后必须核验结果，避免同一工单重复处理。
- 批量执行期间展示当前工单、成功数、失败数、剩余数和倒计时。
- 支持暂停和停止。
- 单条普通失败记录原因并继续下一条。
- 登录失效、网络整体异常、平台字段结构变化或结果不明确时暂停全队列。

## 固定字段

| 平台字段 | 固定值 |
| --- | --- |
| 事件描述 | 保持页面默认引用值，不修改 |
| 原因分类 | 数据疑问 |
| 原因描述 | 已处理 |
| 解决方法 | 修改数据 |
| 解决方案 | 已处理 |

## 安全与恢复要求

- 单条关闭和批量关闭都属于真实平台写操作，执行前必须弹出明确确认框。
- 保存结果不确定时标记为“待核验”，不得直接重复保存。
- 登录失效、网络整体异常或平台字段结构变化时暂停批量队列。
- 日志只记录工单编号、标题、状态和脱敏错误，不记录 Cookie、密码或事件描述。
- 提交清单关闭来源于当前 Excel 中已回填“技术支持编号”的记录，关闭结果回写
  `关闭状态、实际关闭时间、关闭失败原因`。
- 本地 SQLite 记录提交历史和关闭历史，后续可作为自动提交工单的关联来源。

## 已确认边界

- “关闭”只代表完成“受理并总结”，成功状态为 `已解决`。
- 不执行平台上独立的二次关闭操作。
- 批量范围为当前列表中的勾选项。
- 单条普通失败后跳过并继续。
- 关贴间隔从上一条结果核验完成后开始计算，默认随机 5-10 秒，填写固定秒数时按固定值执行。
